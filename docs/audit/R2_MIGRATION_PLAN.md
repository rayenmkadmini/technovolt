# TECHNOVOLT — CLOUDFLARE R2 MEDIA MIGRATION PLAN

**Date:** 2026-11-11  
**Project:** TECHNOVOLT Web Platform (Next.js 16 + Supabase + Cloudflare R2 + Cloudflare Images)  
**Safety Policy:** Zero-Loss Migration · Dual-Read Compatibility · Dry-Run by Default

---

## 1. Architecture Overview

| Layer | Technology | Responsibility |
|---|---|---|
| **Object Storage (Primary)** | Cloudflare R2 (`@aws-sdk/client-s3`, `@aws-sdk/s3-request-presigner`) | Stores immutable binary media objects under UUID-based keys (`media/<folder>/<YYYY>/<MM>/<uuid>.<ext>`) |
| **Image Optimization & CDN** | Cloudflare Images Transformations (`/cdn-cgi/image/...`) | Automatic AVIF/WebP negotiation (`format=auto`), quality `~80`, no upscaling (`fit=scale-down`), responsive widths (`300`, `600`, `1000`, `1600`) |
| **Metadata, Auth & RLS** | Existing Supabase Project (`public.media_assets`, `profiles`) | Stores media metadata, multilingual alt text (`fr`/`ar`/`en`), SHA-256 checksums, migration status, legacy fallback URLs, and enforces admin/content RBAC |
| **Legacy Retention / Rollback** | Existing Supabase Storage Buckets (`media`, `documents`, `lead-photos`, `work-orders`, `receipts`) | Preserved **read-only and untouched** as instant rollback backup |

## 2. Required Environment Variables

Add the following 11 variables in `.env.local` (development) and Vercel/hosting project settings (production). **Never expose `R2_*` credentials or `SUPABASE_SERVICE_ROLE_KEY` via `NEXT_PUBLIC_`, and never commit `.env.local`.**

### Server-Only Variables (Private — Never Commit)
```dotenv
# Cloudflare R2 Object Storage
R2_ACCOUNT_ID=<your_cloudflare_account_id>
R2_ACCESS_KEY_ID=<your_r2_scoped_access_key_id>
R2_SECRET_ACCESS_KEY=<your_r2_scoped_secret_access_key>
R2_BUCKET_NAME=technovolt-media
R2_ENDPOINT=https://<your_cloudflare_account_id>.r2.cloudflarestorage.com
R2_PUBLIC_URL=https://media.technovolt.tn

# Existing Supabase Database & Service Role
SUPABASE_SERVICE_ROLE_KEY=<your_supabase_service_role_key>
```

### Public Client & Delivery Variables (`NEXT_PUBLIC_`)
```dotenv
NEXT_PUBLIC_SUPABASE_URL=<your_supabase_project_url>
NEXT_PUBLIC_SUPABASE_ANON_KEY=<your_supabase_anon_key>
NEXT_PUBLIC_MEDIA_URL=https://media.technovolt.tn
# Optional backward-compatible alias:
NEXT_PUBLIC_MEDIA_PUBLIC_URL=https://media.technovolt.tn
# Keep disabled initially until Gate C (Cloudflare Images verified):
NEXT_PUBLIC_CLOUDFLARE_IMAGES_ENABLED=false
# Optional if transformation zone domain differs from media custom domain:
# NEXT_PUBLIC_CLOUDFLARE_IMAGE_ZONE=https://media.technovolt.tn
```

> **Validation Guardrail:** `src/lib/storage/r2.ts` rejects any `R2_PUBLIC_URL` ending in `.r2.dev` or `.r2.cloudflarestorage.com` or using `http://`. Keep `NEXT_PUBLIC_CLOUDFLARE_IMAGES_ENABLED=false` initially during pre-configuration and staging validation; switch to `true` only after **Approval Gate C**.

## 3. Cloudflare Dashboard Configuration (Manual Prerequisite Steps)

### Step 3.1 — Create R2 Bucket & Scoped API Token
1. In **Cloudflare Dashboard → R2 Object Storage**, create the bucket `technovolt-media` (recommended region: Automatic / EU-closest for Tunisia).
2. Create an **R2 API Token** with permission **Object Read & Write** restricted strictly to the `technovolt-media` bucket (do not use account-wide admin tokens).
3. Record `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, and `R2_ENDPOINT` into `.env.local` / Vercel Secrets.

### Step 3.2 — Bind Custom Media Domain (Mandatory)
1. In **R2 Bucket → Settings → Custom Domains**, connect `media.technovolt.tn` (on a Cloudflare-managed DNS zone).
2. Keep the public `.r2.dev` development URL **disabled**.
3. Verify `https://media.technovolt.tn` serves objects over HTTPS before enabling production uploads.

### Step 3.3 — Configure R2 Bucket CORS Policy
Direct browser uploads use short-lived (`60–300s`) presigned `PUT` URLs generated by `/api/media/presign`. Configure CORS on `technovolt-media` to allow only exact origins, methods, and required upload headers:

```json
[
  {
    "AllowedOrigins": [
      "http://localhost:3000",
      "https://technovolt.tn",
      "https://www.technovolt.tn",
      "https://technovolt.vercel.app"
    ],
    "AllowedMethods": ["PUT", "GET", "HEAD"],
    "AllowedHeaders": [
      "Content-Type",
      "Content-Length",
      "x-amz-meta-original-filename"
    ],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3600
  }
]
```

### Step 3.4 — Enable Cloudflare Images Transformations
1. In **Cloudflare Dashboard → Images → Transformations** (or **Speed → Optimization → Image Transformations** on the target zone), enable **Image Transformations** for the zone hosting `media.technovolt.tn`.
2. Enable **Resize from any origin** **only if needed**, OR keep **Allowed Origins** restricted strictly to:
   - `media.technovolt.tn`
   - Never allow wildcard `*` origins.
3. Verify `/cdn-cgi/image/width=300,quality=80,format=auto,fit=scale-down/...` returns `Cf-Resized` / `200 OK` on a test image.
4. Set `NEXT_PUBLIC_CLOUDFLARE_IMAGES_ENABLED=true` only after verifying transformations return `200 OK`. While `false`, `buildCloudflareImageUrl` serves the clean `R2_PUBLIC_URL` without `/cdn-cgi/image/...`.

## 4. Database & Schema Plan (Phase 3)

Run additive migration `supabase/migrations/005_r2_media_migration.sql` on your Supabase database (never destructive):

1. Reuses `public.media_assets` and preserves all existing columns (`id`, `file_name`, `file_path`, `file_url`, `file_type`, `mime_type`, `file_size`, `width`, `height`, `alt_text_fr`, `alt_text_ar`, `alt_text_en`, `folder`, `uploaded_by`, `created_at`).
2. Adds R2 & migration fields:
   - `storage_provider` (`'supabase' | 'r2' | 'local'`)
   - `object_key` (`text`, unique partial index where non-null)
   - `public_url` (`text`)
   - `original_filename` (`text`)
   - `size_bytes` (`bigint`)
   - `category` (`text`)
   - `sort_order` (`int`)
   - `updated_at` (`timestamptz` auto-maintained via trigger)
   - `migration_status` (`'legacy' | 'pending' | 'verified' | 'failed' | 'skipped' | 'native_r2' | 'rolled_back'`)
   - `legacy_storage_path`, `legacy_public_url`, `legacy_bucket`
   - `checksum_sha256` (`text`)
   - `is_public` (`boolean default true`)
   - `migrated_at`, `deleted_at` (`timestamptz`)
3. Backfills `legacy_storage_path`, `legacy_public_url`, `public_url`, `original_filename`, `size_bytes`, and `category` from existing rows.
4. Updates `public.has_content_access()` to include `super_admin` and restricts `media_assets` writes to `has_content_access() or is_admin()` while public `anon` `SELECT` sees only `is_public = true and deleted_at is null`.

## 5. Phased Cutover Execution Sequence

1. **Validate Credentials & R2 Connectivity (Non-Destructive Probe):**
   ```bash
   node --experimental-strip-types scripts/verify-r2-connectivity.mjs
   ```
   Verifies env vars (without printing secrets) and tests PUT/HEAD/GET/HTTPS/DELETE only on a temporary `__connectivity_check__/probe-*.txt` object.
2. **Apply DB Migration (Approval Gate A):** Execute `supabase/migrations/005_r2_media_migration.sql` via Supabase SQL Editor or Supabase CLI.
3. **Deploy Code + Dual-Read:** Deploy with `NEXT_PUBLIC_CLOUDFLARE_IMAGES_ENABLED=false` initially while Cloudflare Transformations remain disabled; existing `/images/...` and Supabase URLs continue rendering untouched.
4. **Run Legacy Migration Discovery (DRY RUN — Default):**
   ```bash
   node --experimental-strip-types scripts/migrate-supabase-to-r2.mjs
   ```
   Inspect total objects, storage MB, per-bucket counts, missing/inaccessible objects, duplicate groups, DB references, estimated batch duration, and R2 Class A/B usage. Zero bytes or DB rows are modified in dry-run mode.
5. **Execute Batched Legacy Migration (Approval Gate B):**
   ```bash
   node --experimental-strip-types scripts/migrate-supabase-to-r2.mjs --execute --confirm-migration --batch-size=25 --offset=0
   ```
   Wait for SHA-256 verification and `HeadObject` checks on batch 0 before advancing offsets or omitting `--batch-size`.
6. **Enable Cloudflare Image Transformations (Approval Gate C):** Set `NEXT_PUBLIC_CLOUDFLARE_IMAGES_ENABLED=true` once zone transformation verification returns HTTP `200 OK`.
7. **Switch Production Delivery & Retain Legacy Objects (Approval Gates D & E):** Confirm all production pages resolve R2 CDN / transformed URLs cleanly. Retain existing Supabase Storage buckets intact; never delete legacy Supabase objects without separate explicit approval under Gate E. Refer to `docs/audit/R2_ROLLBACK_GUIDE.md` if any revert is ever needed.
